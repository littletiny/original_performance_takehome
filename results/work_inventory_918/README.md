# 918-cycle 版本的计算量压缩候选

当前提交内核是 **918 cycles / 10,811 个静态 VLIW 包**，静态上限为
12,000。本清单先列候选与限制，不把未经验证的改写计入成绩。

## 为什么需要减少算术端口上的工作

固定图的 release/tail 下界是 **915 cycles**，单纯重排该图不能进入 900。
即使允许 ALU/VALU 之间重新分配，当前算术工作仍为：

```text
W = ALU + 8 × VALU = 10,947 + 8 × 5,472 = 54,723
每周期容量 = 12 + 8 × 6 = 60
达到 900 的必要削减量 ≥ 54,723 − 900 × 60 = 723 W
严格 <900，即最多 899 的必要削减量 ≥ 783 W，约 1.43%
```

W 是算术槽位的吞吐权重，并非 FLOP 数或静态指令包数。该必要条件忽略
启动、收尾、依赖和其他端口，因此省下 783 W 并不保证达到 899。
真正消除运算、使用已有融合指令、把合适的工作转移到其他端口，都可能
减少 W；八条 ALU 与一条 VALU 之间迁移不会减少 W。

## 当前成本盘点

| 项目 | W | VALU 槽位 | ALU 槽位 |
| --- | ---: | ---: | ---: |
| hash 内部 | 41,984 | 4,333 | 7,320 |
| 树节点混入 XOR | 4,096 | 309 | 1,624 |
| 路径 bit 提取 | 3,584 | 324 | 992 |
| 路径/地址更新 | 2,848 | 356 | 0 |
| dispatch 打包与 PC 地址 | 768 | 96 | 0 |
| 条件节点复制 | 592 | 0 | 592 |
| MADD 节点选择 | 128 | 16 | 0 |
| 初始化与恢复 | 723 | 38 | 419 |
| **总计** | **54,723** | **5,472** | **10,947** |

以上是各项现有成本，不是承诺能够删除的数量。下面不同方向可能重叠，
不能直接相加估计收益。

## 可枚举的改写方向

| 方向 | 可以尝试消除什么 | 量级与已有证据 | 主要限制 |
| --- | --- | --- | --- |
| 1. hash 阶段融合 | 跨 XOR/shift 的常量合并、重复子表达式、较短的 MADD/XOR 序列、改变内部值的表示 | 512 个八路 hash 组中普遍少一个逐元素操作，毛收益是 4,096 W；H3/H4 已融合 | 加法进位使普通乘加不具备 XOR 线性；已排除若干任意常系数的具体融合模板，尚未证明所有改写不可能 |
| 2. 延续跨轮 XOR 偏置 | 把 H6 的固定 XOR 吸收到随后节点或其他已有操作 | 已处理 384/512 组；剩余 128 组对应 1,024 W | 其中最终一轮占 256 W，输出仍须还原；其余三轮共 768 W。若直接预处理深度 8/9/10 的所有节点，需要 1,792 次节点 XOR，单算预处理已多于收益，尚未计恢复和访存 |
| 3. 路径与地址融合 | 延迟构造中间坐标、折叠两轮路径、把 bit/坐标直接用于 dispatch 地址或节点选择 | bit 与更新共 6,432 W；一整轮 32 组各少一个操作，毛收益 256 W | 不能随意丢弃被后续 hash 或输出使用的位；已测两轮折叠可以减 W，但额外选择、常量和依赖抵消了周期收益 |
| 4. PC 地址生成 | 共用偏移、改变 case 布局、直接生成最终目标，减少 pack/offset/target 中间向量 | 768 W = pack 120 + offsets 288 + targets 360；当前已共用八个指针向量 | 不可能据此假设全部 768 W 可删除；这一项单独的全部成本也小于 783 W；表布局仍须满足 12,000 包 |
| 5. 条件节点复制 | 保留原值供消费者直接使用、合并选择与消费、调整 scratch/向量布局；合适时借 STORE/VLOAD 搬运 | 592 W = 子节点 240 + 孙节点 352 | 运行时选择的来源不能仅靠普通寄存器别名解决；全部消除仍不足 783 W。宽 STORE 方案已试过，新增 LOAD 使成绩变差 |
| 6. 节点选择和 dispatch 结构联合改写 | 用 FLOW 选择替换 MADD，先通过跳转串联或合并释放 FLOW 容量 | 当前 MADD 选择占 128 W；属于端口转移，不必减少总操作数 | 当前 873 个图内 FLOW 在 release 13、tail 10 的窗口中；若保持该窗口，899 cycles 仅容纳 876 个，只有三个槽位余量。单纯大量转到 FLOW 不成立 |
| 7. 初始化、广播和恢复 | 常量/广播共用，复用已读入的根或原始节点，让部分恢复运算不再必要 | 整项 723 W；标量根方案消除了 16 W 的广播，但测得 922 cycles | 大部分初始化与恢复承担必要语义。只缩短恢复依赖属于调度收益，实际删除运算才减少 W |
| 8. 查表层级与 SIMD 分组联合调整 | 改变预取时机、分组和 handler 共享方式，同时减少路径、PC、复制或重复选择 | 可以组合第 3–6 项，避免只消除某个中间量却在别处重新计算 | 已试深度 4 dispatch，较低计数并未带来较低周期；代码共享是否能支持更好分组仍待验证，必须逐项核算静态包、LOAD/FLOW 和 scratch |

建议先按 **路径 + PC + 条件复制的联合消除** 枚举具体图改写，再对
**hash 融合** 做有明确模板的等价性证明。剩余 H6 偏置需要能吸收补偿
成本的新方法，直接扩大全层预处理已不合算。初始化复用适合作为补充。

纯调度、单纯 ALU/VALU 迁移、单纯改善寄存器分配、只压缩静态包，都不
会改变上面的算术容量缺口；它们可以帮助其他改写最终兑现周期收益。

## 复现与依据

```sh
PYTHONPATH=. python3 results/work_inventory_918/run.py
```

脚本逐条分类算术操作，检查总数与图摘要，并与已验证的 918 配置以及
915 下界报告绑定。各类别明细见 `inventory.json`。

- `results/resource_windows_918/`：固定图资源窗口下界。
- `results/xor_918/` 与 `results/xor_pair_synthesis/`：已有 XOR 恒等式及被排除的具体模板。
- `results/cache_followup_918/`：缓存、根复用及较深查表的测量和执行验证。
- `SUB900_WORKLOG.md`：已有路径折叠、PC 共用和静态包约束的记录。
