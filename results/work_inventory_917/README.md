# 917-cycle 版本：先枚举计算量压缩方向

当前正式内核是 **917 cycles / 10,810 个静态 VLIW 包**。目标仍为
**<900 cycles / ≤12,000 包**。本清单更新先前的 918 版本盘点，区分
现有成本、潜在毛收益、已测净收益和已排除的具体表达式。

## 必须减少多少工作

```text
W = ALU + 8 × VALU = 10,932 + 8 × 5,465 = 54,652
每周期算术容量 = 12 + 8 × 6 = 60 W
900 cycles 的必要削减量 = 54,652 − 900 × 60 = 652 W
严格 <900，即最多 899 cycles：至少削减 712 W，约 1.30%
```

W 衡量算术端口承担的工作，并非数学运算次数或静态指令包数。使用更短
等价表达式、把多条运算融合到已有指令、把工作转到其他端口，都能减少
W。八条 ALU 换成一条 VALU，W 不变。

当前固定图结合依赖的资源窗口下界是 **913 cycles**；该图纯重排不能
达到目标。这个下界不约束改变了计算图的实现。712 W 也只是计数上的
必要削减量，尚未扣除启动、收尾、依赖以及其他端口的限制。

## 当前算术成本

| 项目 | W |
| --- | ---: |
| hash 内部 | 41,984 |
| 树节点混入 XOR | 4,096 |
| 路径 bit 提取 | 3,584 |
| 路径/地址更新 | 2,840 |
| dispatch 打包及 PC 地址 | 768 |
| 条件节点复制 | 592 |
| MADD 节点选择 | 128 |
| 初始化、广播、派生常量和树偏置 | 660 |
| **总计** | **54,652** |

表中数字是现有成本，不能当作能够全部删除的收益。后面的方向存在
重叠，特别是跨轮 XOR、hash 融合、路径/PC 和联合 dispatch 改写。

## 候选清单

| 方向 | 具体可能省掉什么 | 收益量级和当前认识 |
| --- | --- | --- |
| 1. hash 内部融合及与节点混入联合改写 | 跨阶段常量 XOR、重复中间量、乘加与 XOR 的较短等价表达式，或一种内部值表示下可合并的边界运算 | 512 个八路 hash 组普遍少一条逐元素操作，毛收益 4,096 W；只覆盖 89 组就有 712 W。H1/H5 的 MADD、H3/H4 融合已经使用。多种单仿射、两仿射 XOR 和乘积模板已被严格排除；不代表所有表达式都不可行。 |
| 2. 扩展跨轮 XOR 偏置抵消 | 让 H6 常量继续与下一轮预偏置节点抵消，或在现有运算中吸收偏置 | 已覆盖 384/512 组。剩余 128 组毛成本 1,024 W，其中最终轮 256 W 没有下一轮可抵消；中间三轮只剩 768 W。直接给深度 8/9/10 的全部节点加偏置，需要 1,792 次节点 XOR，未计恢复就已亏损，必须找到更便宜的补偿方式。 |
| 3. 路径、bit 和节点地址联合计算 | 延迟生成中间坐标，把连续两轮的更新合成最终地址；让已有 bit/选择结果直接服务消费者 | 路径 bit 与更新合计 6,424 W；一整轮 32 组少一条逐元素操作，毛收益 256 W。两轮折叠已有减 W 的正确实现，但增加的选择和依赖抵消了周期收益。仅提前计算 parity 而保留完整 hash，不自动减少工作。 |
| 4. dispatch 的 PC 表示和打包 | 共用偏移向量、直接生成最终 PC、改变 case 编码以删除 pack/path/offset 中间量 | 当前 PC 相关成本 768 W：pack 120、offsets 288、targets 360。现版本已经共享指针向量并折叠一组末尾 bit；进一步压缩需要改变表示或表结构。现有全部成本略大于 712 W，并不意味着可以全部删除。 |
| 5. 条件复制与使用合并 | 让消费者直接用选中节点，合并选择和混入；修改 scratch 或临时内存布局来减少搬运 | 复制共 592 W（子节点 240、孙节点 352），即使全消除也不足 712 W。运行时来源选择不能靠普通寄存器别名消失；宽 STORE 的后续读取、padding、指针和恢复必须一起计费。 |
| 6. 合适的算术转到其他端口 | 把 MADD 节点选择换成 FLOW，把常量生成改用 LOAD，用 STORE/LOAD 布局替代部分 ALU 复制 | MADD 选择共 128 W；常量生成共 116 W。已经迁移 48 个常量到 LOAD。该方向可降低 W，但不保证总操作数下降。需要先释放或找到其他端口的可用窗口。 |
| 7. 初始化及跨输入共用 | 复用已加载的根和原始树块；共用广播、常量、偏置节点和节点差值，减少重复准备及恢复 | 整项剩余 660 W，适合补足其他方案。917 已复用 header 中的根并保留原始深度 4 节点，省掉对应恢复 XOR；这些不能重复计入新收益。运行时输入不同，不能据此共用完整 hash 结果。 |
| 8. 查表层级、分组和 handler 结构联合改写 | 通过更宽分组、共享 handler 或连续区域复用，同时减少路径构造、PC 打包、复制或跳转 | 属于第 3–6 项的组合收益，不能另加一次。它可能释放 FLOW 来承接算术，但朴素扩宽会增加 case 数；必须在 12,000 包内找到可共享的结构。只压缩静态代码本身不减少动态 W。 |

跨轮 XOR 的现有恒等式是：

```text
(value XOR C6) XOR (node XOR C6) = value XOR node
```

其中 node 是运行时树数据，只能在运行期间偏置或缓存，不能视作编译期
常量。XOR 可以跨 XOR/位移搬动，但不能随意跨带进位的加法、乘法抵消。
没有发现可以删除整轮 hash 的恒等式；每轮产生的完整值还要进入下一轮。

## 其他端口限制和实验给出的约束

- 当前 1,760 条 LOAD 距 899 cycles 的总容量 1,798 只差 38 条；实际依赖
  窗口可能更紧。大量增加读取很容易转成 LOAD 瓶颈。
- 当前 874 条图内 FLOW 的最早发射时间为 12、必要尾部为 10；若保留
  这个窗口，899 cycles 只容纳 877 条，只有三个槽的余量。
- 已验证的旧缓存交换候选净省 512 W，却执行 967 cycles；其 LOAD
  依赖窗口给出 916 下界。这说明“算术少了”不是足够的晋升条件。
- 工作区的最新末尾子节点成对布局已实现：七个配对区域的方案净省
  94 W，但执行 927 cycles；只改两个区域的方案为 919。它们通过了
  十个种子的冻结执行检查，但都未替换正式内核。

优先枚举能同时删除路径、PC 和复制中间量的新结构，并核算其 FLOW/LOAD
时机；hash 方向优先提出有明确表达式、可证明等价的新模板。初始化共用
作为补充。纯调度、ALU/VALU 互换、寄存器分配和静态包压缩仍有配合作用，
但它们单独不改变当前算术容量缺口。

## 复现及证据

```sh
PYTHONPATH=. python3 results/work_inventory_917/run.py
```

脚本重新逐条分类默认图、重新计算资源窗口下界，并核对图摘要、正式
内核源码摘要和已保存的冻结验证。此次工作是枚举与核算，没有运行新的
优化搜索，也没有改动正式内核。

- `results/compact_917/`：正式成绩、完整验证及资源窗口下界。
- `results/work_inventory_918/`：前一版本及沿用的分类定义。
- `results/xor_918/`、`results/xor_pair_synthesis/`、`results/product_fusion_918/`：已用恒等式与已排除的具体 hash 模板。
- `results/work_reduction_followup_918/`：缓存交换和两轮地址折叠的冻结成绩。
- `results/late_pair_rows_917/`：工作区研究候选的配置、排程和冻结验证；尚未晋升正式内核。
